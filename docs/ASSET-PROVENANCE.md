# Asset provenance and licensing

## Project code and assets

Every visual element in NEXORA OFFICE 3D is generated by this repository's own source code:

| Asset class | Origin | Licence |
| --- | --- | --- |
| Building geometry, façades, roof, site, stairs, furniture | Procedurally generated in `src/scene/*` | MIT (this repository) |
| Human characters (bodies, faces, hair, clothing, task chairs) | Procedurally generated in `src/scene/character/*` from shared primitive geometries; no downloaded or scanned character model | MIT (this repository) |
| Materials, colours, lighting rig | Defined in `src/scene/materials.ts` and `src/scene/OfficeScene.tsx` | MIT (this repository) |
| Labels, room tags, entrance sign | Rendered at runtime to canvas textures in `src/scene/Labels.tsx` | MIT (this repository) |
| Live desk screens (activity, task, clock) | Composed and painted at runtime to per-monitor canvas textures in `src/scene/character/deskScreens.ts`; system fonts only | MIT (this repository) |
| Environment reflections | `RoomEnvironment` shipped with three.js, generated in-memory (no HDR file) | MIT (three.js) |
| Icons | Unicode glyphs, no icon font | — |
| Typography | System font stack (`Inter` if installed locally, then platform UI fonts); no webfont is downloaded | — |
| Floor plans, department layout, agent names, tasks | Original fixtures authored for this project | MIT (this repository) |

No textures, 3D models, photographs, icon sets, audio or third-party design files are downloaded or bundled.
There is no external asset host in `next.config.ts`.

### Characters specifically

- The characters are not derived from any third-party rig, mesh, texture or animation clip. They are assembled at
  runtime from unit box/sphere/cylinder geometries defined in `src/scene/materials.ts`.
- All pose, idle, walk, sitting and typing motion is authored as trigonometry in `src/scene/character/pose.ts`; no
  mocap data, Mixamo clip or purchased animation library is used.
- Faces, hairstyles, clothing and size variation are seeded from the agent id, so every look in the scene is generated
  by this repository's own code.
- Navigation and behaviour are equally original: the occupancy grid, A\* search, corridor lanes, lift journeys,
  avoidance rules, activity finite state machine and meeting-seat allocation were written for this project
  (`src/scene/character/navigation.ts`, `journey.ts`, `activity.ts`, `activitySystem.ts`). No third-party pathfinding
  library, behaviour tree, animation state machine or scheduling package is installed.

## Reference project boundary

The brief cites the **Agents Office** project as inspiration. It was used for conceptual orientation only — the general
idea of a 3D office with agents, rooms and status indicators.

- No source code, assets, data files, copy or implementation details from that project were copied, renamed or
  repackaged.
- The spatial data model, procedural geometry system, camera choreography, state machine, execution-port abstraction,
  interface and copy in this repository were written from scratch for this task.
- If any material from that project is ever reused, its licence and written authorisation must be reviewed first; that
  is explicitly out of scope here.

## Data and privacy

- `src/data/agents.json` and `src/data/tasks.json` are fictional demo data. The names are synthetic and do not
  describe real people or companies.
- No analytics, cookies, tracking scripts or third-party requests are included in the client bundle.
- The live execution bridge keeps its endpoint and token server-side; the browser only sees this app's own
  `/api/executions` route.
